# Feature Specification: MusicXMLの複数バージョン取り込みと旧importer互換性

**Feature Branch**: `007-musicxml-version-compat`（仕様作成時は006、実装開始時に専用ブランチへ分離）

**Created**: 2026-10-19

**Status**: Draft

**Input**: User description: "MusicXML取り込みの対応範囲を4.0以外にも拡張する。旧importerを調査し、以前読み込めたファイルとの互換性を回復する。MusicXML 2.0・3.0・3.1・4.0について対応範囲を明示する。音高・音価・声部・和音・拍子・調号・テンポを保持し、未対応要素は警告または利用不可の理由として示す。MXLの安全な展開と既存の入力制限を維持する。Menuett_in_G-Dur_BWV_Anh._114.mxlを回帰検証の対象にする。"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 以前利用できた楽譜をそのまま取り込む (Priority: P1)

利用者はリポジトリを作成または選択し、MusicXML 2.0・3.0・3.1・4.0の楽譜をアップロードする。バージョンの書き換えや別形式への書き出し直しをせず、内容を確認して保存できる。

**Why this priority**: 従来読み込めた楽譜を形式の版だけで拒否される問題を解消し、楽譜の利用を再開できる。

**Independent Test**: 各対象バージョンの同じ音楽内容を持つXMLとMXLをアップロードし、プレビュー確認から保存、保存後の再表示まで完了する。旧importer由来の回帰楽譜でも確認する。

**Acceptance Scenarios**:

1. **Given** 編集可能なリポジトリと対象4バージョンの対応範囲内の楽譜、**When** XMLまたはMXLをアップロードする、**Then** バージョンを理由に拒否されず、プレビューを確認して保存・再表示できる。
2. **Given** 旧importerで読み込めた実ファイル `Menuett_in_G-Dur_BWV_Anh._114.mxl`、**When** 新規リポジトリの作成後にアップロードする、**Then** 実際の宣言バージョンと内容に基づいて処理され、対応範囲内の内容を保持したプレビューと保存結果が得られる。未対応要素があればUS3の説明と利用可否になる。
3. **Given** 既に利用できている4.0の楽譜、**When** 同じ楽譜を再度取り込む、**Then** 保持対象の音楽情報と保存・表示・練習の利用可否に意図しない変化がない。

---

### User Story 2 - バージョンが違っても同じ音楽情報を利用する (Priority: P1)

利用者は、複数声部・複数段・複数パートや和音を持つ楽譜について、元の音符の位置と長さ、拍子・調号・テンポを保った結果を確認する。変換によって異なる音や演奏時刻に置き換わらない。

**Why this priority**: 読み込み成功だけでは不十分で、誤った音楽情報による表示・演奏・練習を防ぐ必要がある。

**Independent Test**: 元の音楽内容と期待値を独立して定めた各版の楽譜を使い、取り込み直後と保存後の音楽情報を照合する。

**Acceptance Scenarios**:

1. **Given** 音高、開始位置、音価、休符、声部、和音、パート・段構成が分かる対象バージョンの楽譜、**When** 取り込む、**Then** それらが保持され、声部の重なりや和音を単音列へ変えない。
2. **Given** 途中で拍子・調号・テンポが変わる楽譜、**When** 取り込み結果を確認して保存する、**Then** 各値と適用位置が保持され、保存後の表示・演奏・練習でも同じ内容を利用できる。
3. **Given** 同じ音楽内容を表す2.0・3.0・3.1・4.0の対照楽譜、**When** 取り込む、**Then** 保持対象の音楽情報はバージョンを除いて同等になり、読み取った元のバージョンを結果で確認できる。

---

### User Story 3 - 未対応・不完全な内容を理解して判断する (Priority: P2)

利用者は、単に「対応していません」と表示される代わりに、対象外の版・文書構造、不正な内容、表示上の省略、演奏に影響する未解決事項を区別して理解する。

**Why this priority**: 再試行や元ファイルの修正が必要か判断でき、誤った音楽情報を正しい結果と取り違えない。

**Independent Test**: 表示情報の省略、演奏順の未対応、音高や音価の欠落、対象外バージョンを含む楽譜を取り込み、説明・保存可否・練習とゲームの利用可否を確認する。

**Acceptance Scenarios**:

1. **Given** 演奏内容は保持できるが表示情報の一部を扱えない楽譜、**When** プレビューを見る、**Then** 省略内容の警告を確認でき、表示情報の省略だけを理由に演奏を禁止しない。
2. **Given** 音高・時刻・演奏順などを確定できない楽譜、**When** 取り込む、**Then** 黙って値を捏造せず、対象と理由を示す。安全に残せる内容は既存の不完全な楽譜の確認・保存手順で扱い、未解決のまま練習・ゲームを開始できない。
3. **Given** 対象外・不明なバージョンまたは対象外の文書構造、**When** 取り込む、**Then** 対応する版・文書構造と拒否理由を判断できる案内になり、保存データは変化しない。

---

### User Story 4 - 安全性と既存データを保って取り込む (Priority: P2)

利用者は、対応版が増えても既存の入力上限や権限の下で取り込みを行う。不正なMXLや中断・失敗によって既存の楽譜・リポジトリが壊れない。

**Why this priority**: 互換性を回復するために安全性や保存済みデータの信頼性を落とさない。

**Independent Test**: 上限内外の入力、不正なMXL・XML、取消・失敗・再試行、権限不足の操作を実行し、結果と保存済みデータを確認する。

**Acceptance Scenarios**:

1. **Given** 展開上限超過、不正な格納先、外部情報の参照を要求する内容を含む入力、**When** 取り込む、**Then** 制限に従って拒否され、外部取得や格納先外への書き込み、既存データの部分更新を行わない。
2. **Given** 保存済み楽譜と編集中の入力、**When** 取り込みが失敗するか取り消す、**Then** 保存済み楽譜は変化せず、既存の再試行手順を利用できる。編集権限のない利用者には保存を許可しない。

### Edge Cases

- 対象4版の各宣言と、宣言と内容の不一致、宣言欠落、未知の版、対象外の版。宣言番号だけを変更したファイルを受け入れることは互換性の証明としない。
- `score-partwise` と `score-timewise`、複数楽曲を束ねる文書。後二者の新規対応は範囲外として説明する。
- 正常な公開文書型宣言を持つ旧版の楽譜と、不正な宣言・内部実体定義・外部実体参照を持つ楽譜。正常な宣言は外部取得せず扱う。
- MXLの複数rootfile、ルート楽譜の欠落、重複または危険な格納先、破損圧縮、小さな圧縮ファイルからの過大な展開。
- 弱起、複数声部の時刻移動、和音、休符、タイ、複数段・パート、途中の拍子・調号・テンポ変更、パート間の時刻や設定の矛盾。
- 音高・音価が欠落する音符、微分音、装飾音、反復・別エンディングなど、現在の演奏表現で確定できない内容。
- テンポ等の省略と不正値を区別する。テンポ0・負数など形式・値域が不正な設定値は拒否し、有効だが解釈不能な指示・パート間の矛盾はBLOCKINGとする。省略に対する既存の既定値補完はWARNINGで内容を示し、不正値や不明な音高・音価を既定値で埋めない。
- 上限ちょうどの入力と超過、変換中の取消、画面離脱、通信失敗後の再試行。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: MusicXML 2.0・3.0・3.1・4.0の `score-partwise` を、非圧縮XML（.xml/.musicxml）と圧縮MXLの双方で受け入れなければならない。対応範囲内の内容は、版が4.0でないことだけを理由に拒否してはならない。
- **FR-002**: 各対象バージョンについて、保持できる音楽情報、警告となる表示上の省略、未解決なら練習・ゲームを禁止する表現、拒否する文書を列挙した対応表を整備し、利用者向けの対応形式案内を一致させなければならない。対応版の表明を各版の全要素への完全対応と扱ってはならない。
- **FR-003**: 旧importerが扱った入力・変換結果と現在の結果を比較し、互換性の差を記録しなければならない。以前読み込めた対象4版の楽譜は保持対象を回復する。ただし、旧実装の情報欠落や不正値の黙認を再現する必要はなく、その相違は理由と影響を明示しなければならない。
- **FR-004**: 対応範囲内の音高、開始位置、音価、休符、声部、和音、タイ、パート・段構成を保持しなければならない。拍単位の位置・長さと演奏時間の関係を維持し、別の値へ黙って丸めたり置換したりしてはならない。
- **FR-005**: 拍子・調号・テンポの値と変化位置を保持しなければならない。不正な形式・値域の設定値は、理由を示して取り込みを拒否する。有効だが解釈できない指示やパート間の矛盾は、BLOCKINGとして示し、未解決のまま練習・ゲームを許可してはならない。省略時に既存の既定値を補完した場合は、補完内容を警告する。
- **FR-006**: 表示だけの省略は警告として示し、演奏に影響する欠落や未対応の演奏順は利用不可の理由として示さなければならない。識別可能な場合は該当パート・小節・音符または項目を示し、安全に保持できる不完全な内容には既存の確認・修正・保存手順を適用しなければならない。
- **FR-007**: 対象外・不明なバージョン、および標準DOCTYPEでも確定できない欠落バージョン、対象外の文書構造、不正または破損した入力、上限超過について、原因の種類と利用者の次の行動を判断できる案内を返さなければならない。対象4版のいずれかへ黙って読み替えてはならない。
- **FR-008**: 取り込み結果は実際の元ファイルのMusicXMLバージョンを識別可能に保持する。rootのversion属性が欠落している場合に限り、score-partwiseと一致する標準PUBLIC DOCTYPEに2.0・3.0・3.1・4.0が明記されていればその版を使い、DOCTYPE由来であることを通知する。版が不明・対象外、明示したroot版とDOCTYPE版が矛盾する場合は復元せず、異なる版を一律に4.0として扱ってはならない。
- **FR-009**: MXLのルート楽譜選択、格納先検証、展開量・件数の制限、外部実体の禁止を維持しなければならない。対象版で通常使われる公開文書型宣言は、外部情報を取得せずに扱い、内部実体定義等の危険な入力を許可してはならない。
- **FR-010**: 既存の上限（入力5MiB、総展開20MiB、100件、10,000音、変換10秒、利用者ごと同時1要求）および既存の全体同時実行・処理資源上限を緩めてはならない。管理設定でさらに低くした上限も維持しなければならない。
- **FR-011**: 認証・リポジトリ権限・保存前の確認・取消・同じ入力の再試行を維持し、失敗や取消で保存済みデータを部分更新してはならない。新しい取り込み結果はプレビュー時と保存後で保持対象の内容・確認事項・利用可否が一致しなければならない。
- **FR-012**: 保存済みの楽譜・過去の取り込み結果は再変換や移行を要求せず利用できなければならない。既存4.0、MIDI、楽譜JSONの入力・保存・表示・演奏の挙動を悪化させてはならない。
- **FR-013**: 各対象版に固有の実際の表現を含むXMLとMXL、旧importer由来の回帰楽譜、既存4.0、不正・境界入力を、期待する音楽情報と利用可否とともに回帰検証の対象としなければならない。原本・出所・利用条件を記録し、単なる版番号の置換試験だけで対応完了としてはならない。
- **FR-014**: `Menuett_in_G-Dur_BWV_Anh._114.mxl` の実ファイルで、リポジトリ作成後のアップロード、プレビュー、確認・保存、保存後の再表示を検証しなければならない。未対応表現がある場合は理由と利用可否まで照合する。原本を入手できない間はこの検証を未実施と明示し、同名の別ファイルや合成楽譜で成功したと代替報告してはならない。

### Key Entities _(include if feature involves data)_

- **元の楽譜**: XMLまたはMXLの入力。宣言バージョン、文書構造、内容、出所・利用条件を持ち、変換結果と対応付ける。
- **対応範囲**: 対象バージョンと文書構造に対し、保持・警告・利用不可・拒否の条件を示す一覧。
- **変換結果**: 保持した音楽情報、元バージョン、確認事項、保存・練習・ゲームへの利用可否。プレビューと保存後の内容を照合する単位。
- **回帰楽譜**: 原本と独立に確認した期待値・期待する制限を組にした検証対象。旧importerとの比較やバージョン間比較の根拠になる。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 対象4版×XML/MXLの8組すべてで、対応範囲内の代表楽譜を手動の版変更や再書き出しなしにアップロード・確認・保存・再表示できる。
- **SC-002**: 各版の回帰楽譜で、FR-004/005の保持対象を期待値と照合し、音高・位置・長さ・構成・設定値と変更位置の意図しない差が0件である。表示時と保存後の結果も一致する。
- **SC-003**: 対応表の全分類について代表例を検証し、警告・利用不可・拒否が説明と100%一致する。未解決の演奏上の問題がある例を練習・ゲームで利用可能と誤判定する例は0件である。
- **SC-004**: 旧importerとの比較対象全件で、回復した互換性または安全性・正確性のため残す制限を説明できる。報告されたMenuettの実ファイルでもFR-014の一連の操作と結果を確認し、未実施のまま互換性回復を完了扱いにしない。
- **SC-005**: 上限・不正入力・取消・権限不足の検証対象全件で、制限回避、外部取得、格納先外の書き込み、既存データの部分更新が0件である。変換の成功または制限時間超過の通知は既存の10秒上限を維持する（アップロード・通信時間を除く）。
- **SC-006**: 既存4.0・MIDI・楽譜JSON・保存済み楽譜の回帰検証で、保持対象の音楽情報と従来の保存・利用可否の意図しない変化が0件である。

## Assumptions

- 対象は2.0・3.0・3.1・4.0の `score-partwise`。1.x・4.1以降、`score-timewise`、複数楽曲を束ねる文書の新規対応や完全なMusicXML全要素対応は含めない。これらは拒否時に範囲を説明する。
- 現行のバージョン限定と、旧importerに同じ限定がなかったことは調査で確認した。ただしMenuett原本は実装後に利用者がfixturesへ追加した。rootにversion属性がなく、標準PUBLIC DOCTYPEが3.0を明記するため、従来の「欠落は一律拒否」をFR-008の限定復元に改める。DOCTYPE未指定やSYSTEM URLだけでは版を確定しない。
- 新しい版の受け入れと元バージョンの保持は今後の取り込みに適用する。既存データを再解釈・上書きせず、過去の記録から失われた元バージョンを推測して補わない。既存データの移行は不要とする。
- 反復展開、微分音や装飾音などの新しい演奏機能は今回の目的に含めない。旧版の異なる記法で同じ対応済み内容を表せる場合は読み取り、演奏の意味を確定できない場合は理由を示す。
- 既存のリポジトリ作成・選択、認証・認可、保存・不完全な楽譜の修正、再試行の流れを利用する。MIDIやJSONの対応拡張、採点・描画方式の変更、UI全体の再設計は範囲外とする。
