# Data Model: 認証UIのHeroUI統一

## 永続モデル

追加・変更なし。User、Account、PasswordCredential、セッション、確認案内、本人確認証明、通知jobは[仕様002](../002-email-password-login/data-model.md)と既存実装を維持する。migration、保存形式変更、状態移行は不要。

## 既存の画面内状態

以下は既存のReact状態・処理を説明するもので、新しい保存用エンティティや共通状態モデルを導入しない。

| 状態       | 内容・所有者                                                | 制約                                                                                           |
| ---------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 入力       | email、password、currentPassword、newPassword。各画面が所有 | メールは既存emailSchemaで検証。パスワード原文を保持し15〜128コードポイント。不正サロゲート拒否 |
| 送信       | pending、AbortController。既存ref/hookが所有                | 処理中は再要求を拒否。unmountでabortし、遅延結果を描画しない                                   |
| 結果       | message、sent、complete。各画面/hookが所有                  | 公開可能な日本語案内のみ。入力エラーと共通サーバー案内を区別する                               |
| 確認リンク | ConfirmationLinkのpurpose/token                             | fragment除去後メモリーのみ。表示合成部品へ渡さない。成功時clear。再読込は再要求                |
| 利用条件   | githubAvailable、hasEmail、既存credential有無               | サーバーから既存の公開bool/分岐だけ。秘密の設定値や認可判断をUIへ移さない                      |

## 表示用部品の境界

- AuthPanel: title、childrenを受ける表示合成。認証状態や秘密を解釈しない。
- AuthFeedback: messageを受ける結果通知。token・入力値・生の例外を受けない。空messageでは通知本文を表示しない。
- InputのisInvalid/errorMessageは既存スキーマのローカル入力エラーから導く。APIの共通案内を「登録済み」等のフィールド状態へ変換しない。

## 状態遷移

1. 入力中→既存検証失敗: 入力を維持し、該当欄に条件とエラーを関連付ける。通信なし。
2. 入力中→送信中: 既存submitのロック取得後、loading/disabledを表示する。
3. 送信中→失敗: 共通の安全な案内を表示し、再試行可能へ戻す。不要なフォーカス移動をしない。
4. 登録/再送成功: 共通案内、sent状態、パスワード消去。確認前の自動ログインなし。
5. RESET要求成功: 共通案内を表示。確認リンクでの明示確定を待つ。
6. 確認/変更成功: 秘密を消去し、入力を終了して通常ログインを案内する。既存のセッション更新・全端末失効を維持する。
7. 追加: 既存のGitHub本人確認→メール要求→同一ブラウザーのADD確認を維持する。追加の必須ステップなし。
8. 画面離脱: 既存abortと確認リンクの寿命に従い、遅延結果を表示しない。

共通表示部品はこれらの遷移を実行しない。成功後の個人情報非表示は既存AuthenticationVisibility/getSession経路を維持する。
