# Contract: 既存描画と応答性の保持

## 1. 外部契約

既存の取り込み・警告確認・再検証・保存・読込・権限契約は変更しない。新規HTTP endpoint、保存形式、converterVersion、diagnosticの意味は追加しない。対象原本の期待値は007から引き継ぐ。

Viewerは処理中をrole=status、表示失敗をrole=alertと再試行で伝える。既存のフォーム取消・ページ離脱・表示条件変更が描画待機中にも操作できる。取り込み中のfetch取消と描画ジョブの取消は別責務で接続し、表示取消が保存やcanPractice変更を起こさない。

## 2. 描画の呼出・公開契約

- 既存の同期Score.import、Controller.mount/toDocument、Document.toSVGは利用可能に保つ。計算は共通のステップ/要素生成へ集約し、同期/協調経路で異なる数式を持たない。
- ブラウザーは入力snapshotとoptions、signalを使う非同期のrender adapterを利用する。snapshot→私有Score→Document→detached SVG→highlight bindingの完了値を返す。中間Score/DOMをUIやaudioへ公開しない。
- 各jobは単独のmutable graphを持ち、8ms目標の処理予算を越える前後に実タスクへyieldする。Promise.resolveだけのmicrotask継続は不可。モデル生成、sort/tie、SVG再帰、ハイライト全音符接続も長時間の一括処理を残さない。
- 最新世代だけをcommitし、古い成功/失敗/取消は現在の状態を上書きしない。終了時はtimer・signal購読・observer・highlight callback・未公開DOMを解放する。
- 成功時のnote/source ID、glyph class、scroll-on-highlightは既存の最新SVGと接続。ページ切替後もハイライトの重複購読を残さない。
- 失敗は表示段階の安全なメッセージとし、音楽情報の欠落・未対応による既存診断と区別する。

## 3. 固定した性能予算

対象は既存の許可範囲内。全体変換上限を増やさない。以下は描画のみの採否基準。

| 指標 | 開始→終了 | 原本の合格予算 |
| --- | --- | --- |
| model cold | 検証済み候補からScore構築開始→Document完了 | 6,500ms |
| browser cold / reload | 候補が画面で利用可能→SVG公開・必要なbinding完了・次のpaint | 12,500ms |
| conditions redraw | 表示条件変更イベント→新条件のSVG公開・次のpaint | 6,500ms |
| input / cancel / leave | ブラウザーの入力受理→対応する更新・取消状態・遷移先の画面枠/見出しの表示 | 100ms |
| page navigation | ページ操作→選択ページの公開・次のpaint | 100ms |
| scheduler slice | yield間のアプリ描画処理 | 目標8ms。操作応答100msは別に必須 |

coldには初回のモデル検証・構築、レイアウト、SVG生成、bindingを含む。候補到着前のアップロード・変換・通信、利用者が警告を読む時間、フォント/音源のネット取得は除外する。保存後は詳細データ受領を開始点にする。フォントは事前ロードし、ネット負荷を分離。音声モデル準備を並走させても画面応答の予算は守る。音源をロードしない条件だけで通常表示の合格を主張しない。

**根拠**: 単独計測の準備合計最大3,038.4msの2倍/4倍を切上げて6.5s/12.5sとした。8msは100ms応答のため細かく制御を戻す設計予算。操作100msは小素材のモデル約10msへ余裕を持たせた目標。ブラウザーの達成可能性を計測済みとは主張しない。

## 4. 測定条件と集計

- 参照資源はmeasurements/baseline.json。同一ホストで改善前後を比較し、他の描画・ビルド・単体スイートを並走させない。別資源での測定は別シリーズとして識別し、目標を黙って緩めない。
- 実Chromium、1280×900と360×800、scale12/18、Horizontal/Vertical/Page、advanced=true/debug=false。debug=trueは結果保持の回帰に含め、性能の主要合否と分ける。
- 入力は固定hashの原本、quarter_middle_c、および既存のタイ・臨時記号・TAB・打楽器・複数段代表。実装前に代表パス/hashを測定manifestへ固定する。
- 各fixture/表示条件についてfresh Score・新jobのcold5回、同じsnapshotで条件往復/retry5回。モデルのみはfresh Node process、ブラウザーcoldは新ページ、warmは同じページ。中央値/最大値/全試行を記録し、平均で外れた停止を隠さない。
- 操作応答は描画中を含め各試行で入力、取消、離脱を投入し、下記の同一時計・開始終了点で入力待ち時間を含めて記録。計測用heartbeat/long-taskは補助で、実操作の代わりにしない。取消の破棄と現在世代の公開を独立に確認する。
- ページ遷移は前後ページを往復。条件再描画は直前の表示方式/幅/倍率と変更後を記録する。
- 専用の計測は1試行30秒で打切り、未完了として不合格。変更前の原本は同じ30秒の上限付きで測定し、下限として記録する。低速な基準描画採取は別offline処理であり性能試行に混ぜない。
- 小素材と既存代表の非悪化: 各同一条件で新最大値が `max(旧最大値×1.20, 旧最大値+20ms)` 以内。まず変更前5試行を取得して閾値を固定。原本の打切り値から改善率を計算しない。
- 全試行が該当予算を満たし、失敗・打切り0で合格。時間目標未達時に入力上限・画面応答・描画保持を弱めない。

### 操作応答の時計・開始点・終了点

操作応答時間は、ブラウザーが入力を受理した時点から、対応する画面更新が表示されるまでとする。イベント処理開始前の待ち時間も含める。イベントハンドラー開始時刻を測定開始点にしてはならない。

- **時計**: 実Chromiumのブラウザートレース上の単調増加時計を基準とする。入力受理、対応するイベント処理開始、状態反映、更新を含むフレームの表示時刻を対応付けて記録する。ページ内のEvent.timeStamp/Performance値を併用する場合はtime originとの対応を記録し、同じ時間軸へ換算してから差を取る。自動操作ツール側の壁時計や異なるページのperformance.nowをそのまま減算しない。ナビゲーションをまたぐ場合もトレース時計で対応付ける。
- **開始点**: 自動操作命令の発行・完了やハンドラー開始ではなく、ブラウザーが当該入力を受理した記録。入力ごとに識別子を付け、待ち行列で停止していた時間を除外しない。記録が欠落した試行は計測不能とし、100ms以内の成功として集計しない。
- **終了点**: 通常入力は対応する変更状態の表示、取消は取消状態の表示、離脱は遷移先の画面枠・見出しの初回表示、ページ切替は選択ページのSVGの表示。離脱先での楽譜全体の描画は別途cold/reload予算で測定し、画面枠だけで楽譜描画完了を主張しない。
- **表示の証拠**: 対応する状態が反映されたDOM更新と、その更新を含む表示フレームをトレース/画面記録で確認する。requestAnimationFrameのコールバック実行やDOM置換だけを表示完了とは扱わない。フレームと状態の対応が確定できない試行も計測不能とする。
- **保存する値**: input ID、操作種別、page/generation識別、時計対応、inputReceived、handlerStart、stateCommitted、framePresented、inputDelay、全応答時間、計測可否を記録する。合否は `framePresented - inputReceived <= 100ms`。inputDelayは診断用であり、合否時間から差し引かない。秘密値・実ユーザーの入力本文は保存しない。

この計測機能はT003で用意し、T005の変更前基準と改善後のT018/T025/T031/T033で再利用する。変更前の停止・打切り・計測不能もそのまま記録し、性能改善後に時計や終了点を変更して合格へ寄せない。

## 5. 正確性の独立した合否

1. **音楽意味**: 原本hash、全5,540音、和音/タイ/弱起/設定、元版3.1、診断312件、保存前後の候補・metadata・validationが007の期待値と一致する。
2. **Document**: 要素種別・glyph・source/IDs・順序・全座標・曲線・page/row寸法を、凍結した旧実装の出力と比較する。数値を丸めて違いを隠さない。
3. **SVG**: 属性順・生成font family名だけ正規化し、記号・source ID・構造・幾何属性・ページ構成を比較。表示方式×幅×倍率の同条件へ戻ると結果が一致する。
4. **目視**: Bravuraロード済みのスクリーンショットで音符/連桁/タイ/臨時記号/改行/ページを確認。DOM構造試験を目視成功と混同しない。
5. **所有期間**: 待機・失敗・取消・離脱・A→B切替を制御した全ケースで、stale commit0・意図しない保存0・継続購読0。同じsnapshot/改訂と新しい条件の取り違え0。

原本の旧Document全体は製品変更前のソースコピーをoffline実行して取得し、最大30分の外側期限を設ける。期限超過時は未取得とし、原本全体の描画保持をPASSにしない。取得完了または同等に独立した検証可能な基準の確立前に、基準取得タスクを完了扱いにしない。

## 6. 要件対応

FR-001/007/008/011、SC-001/003: 原本実操作と007の保存回帰。FR-002/010、SC-002/006: 上記時間・非悪化測定。FR-003/004/005/009、SC-003/004/006: 意味・旧Document/SVG・条件往復。FR-006/008、SC-005: 世代/取消/失敗/離脱・保存非更新試験。全9受入シナリオを実装時の結果表へ対応付ける。
