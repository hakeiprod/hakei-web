# Feature Specification: 楽譜描画の基礎回帰・タイ・臨時記号

**Feature Branch**: `chore/setup-spec-kit`（既存ブランチ。ブランチ作成フックなし）

**Created**: 2026-10-20

**Status**: Draft

**Input**: 楽譜の取り込み・保存・描画を調査し、未対応・情報欠落・表示不具合を整理する。対象記号を取り込み、保存、再読み込み後にも保持・表示する。表示と再生・練習・採点への影響を区別する。notehead や tie など可能な限り小さい確認単位の fixtures を増やし、条件再現に必要なら大きい入力も許容する。

**Scope Decision**: 利用者回答「基礎記号の回帰＋タイ＋臨時記号（推奨）」により確定。P1/P2 とも今回の必須対象。スラー・連符表示・強弱・奏法記号は後続候補。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 基礎記号を小さな楽譜で確認する (Priority: P1)

利用者・開発者は確認用楽譜ごとに確認対象と期待表示を読み、符頭などの記号が意図どおり描かれたか判断できる。

**Why this priority**: 描画処理の完了だけでは記号の欠落を検知できず、機能追加時の安全性を判断できない。

**Independent Test**: 4分音符の符頭を主な対象とする楽譜で、符頭の種類・数・五線上の位置を検証する。符頭が欠落した結果は不合格となる。

**Acceptance Scenarios**:

1. **Given** 基礎記号ごとの確認用楽譜、**When** 一覧で表示する、**Then** 対象と期待結果が分かり、各条件の合格・不合格・未検証を区別できる。
2. **Given** 描画処理が完了しても対象記号が欠けている結果、**When** 検証する、**Then** 対象条件は不合格となる。
3. **Given** 休符や全音符に不要な符幹・旗が付いた結果、**When** 不在条件を検証する、**Then** 誤描画を検知できる。

### User Story 2 - タイを保存後も正しく読む (Priority: P1)

利用者はタイ付きの楽譜を取り込み、プレビューと保存後の表示で同じ音のつながりを読める。

**Why this priority**: タイは保持経路がある一方、現行描画に出力がなく、継続する音を読み違えるおそれがある。

**Independent Test**: 同小節内の2音を結ぶタイを取り込み、保存・再読み込みの前後で対象音と表示を確認する。

**Acceptance Scenarios**:

1. **Given** 同小節内・小節越え・3音以上の連鎖の各タイ、**When** 取り込み、保存して再表示する、**Then** 対象の符頭を結ぶタイがすべて表示される。
2. **Given** 和音の一部の音だけにタイがある楽譜、**When** 表示する、**Then** 対象音だけが接続され、別の声部・譜表・パートの同音へ誤接続しない。
3. **Given** 改行・改ページをまたぐタイ、**When** 該当レイアウトで表示する、**Then** 両側に継続を示すタイが見え、切れ・はみ出し・別音への接続がない。
4. **Given** 音楽的なタイの意味が確定した楽譜、**When** 表示と再生・練習・採点を比較する、**Then** 描画追加による余分な再打鍵や開始位置・音価・採点対象の変更がない。
5. **Given** 始点・終点の欠落や接続先の曖昧さ、**When** 取り込む、**Then** 勝手に接続せず、表示上の制限か演奏上の未解決かを示す。

### User Story 3 - 臨時記号と音名表記を保持する (Priority: P2)

利用者は異名同音や臨時記号を原譜に沿って読み、保存後も同じ表記を確認できる。

**Why this priority**: 演奏音高が同じでも音名と五線上の位置は異なり、音高だけの保持では原譜の表記を再現できない。

**Independent Test**: C♯ と D♭、および変化音を戻すナチュラルを別々の楽譜で取り込み、保存後の位置と記号を比較する。

**Acceptance Scenarios**:

1. **Given** シャープ・フラット・ナチュラル・ダブルシャープ・ダブルフラットの各楽譜、**When** 取り込み、保存して再表示する、**Then** 音名・オクターブ・変化量と明示記号が保持され、演奏音高を変えず正しい位置に表示される。
2. **Given** 同小節で変化音を反復し、ナチュラルと次小節の音が続く楽譜、**When** 表示する、**Then** 調号と小節内の状態に従い必要な記号が表示され、小節境界で状態がリセットされる。
3. **Given** 注意喚起のため明示された記号と括弧付き記号、**When** 保存して再表示する、**Then** 明示指定と括弧が保持され、自動省略されない。
4. **Given** 複数声部・譜表・パート・異なるオクターブの臨時記号、**When** 表示する、**Then** 明示指定を優先し、自動判定は定めた範囲でのみ状態を共有する。

### Edge Cases

- 表記情報のない旧保存楽譜・MIDI由来の楽譜は、従来の音高と調号による推定を使う。原譜の表記を復元したと扱わない。
- タイをまたぐ臨時記号、調号変更との併用は、単独条件とは別の組み合わせ回帰を用意する。
- 和音内の同音・隣接音、上下符幹、加線と対象記号の併用でも対象音を判読できる。
- 音楽的タイ指定と視覚的タイ指定が片方だけある場合、一致する場合、矛盾する場合を区別する。視覚指定だけで演奏タイを新設しない。
- 音名表記と演奏音高が矛盾する入力は理由を返し、保存済み楽譜を部分更新しない。
- 未対応の微分音・特殊記号を通常の音や記号へ黙って置換しない。
- 改行・改ページに必要なら fixture の音符・小節数を増やし、その理由を記録する。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 取り込み・保存・再読み込み・描画・再生／練習／採点について、対象表現ごとの対応状況・情報欠落・優先順位・根拠を一覧化する。静的に確認した欠落と、未実行の表示確認を区別する。
- **FR-002**: 新規対応はタイと、通常の12平均律で表せる音名表記・臨時記号（♯・♭・♮・ダブルシャープ・ダブルフラット、明示・注意喚起・括弧表示）とする。
- **FR-003**: 基礎回帰は通常符頭と休符の全音符・2分・4分・8分・16分の各音価、付点、上下符幹・旗、連桁・フック、和音、上下加線、ト音・ヘ音記号、調号、拍子・拍子変更、通常・終止小節線、複数譜表を対象とする。各音価・各条件を個別に判定できること。
- **FR-004**: 対象情報は対応入力からプレビュー、保存、取得、再表示まで保持する。モデル内の書き出し・読み込みだけでなく、実際の保存・取得経路も確認する。
- **FR-005**: タイの対象音・声部・譜表・パートと始点・終点・連鎖を保持し、同小節・小節越え・改行・改ページで正しい符頭へ表示する。
- **FR-006**: 音楽的タイと視覚的タイを区別する。音高・開始位置・音価・打鍵連結・再生・練習・採点の意味を描画の都合で変更しない。不整合は理由と影響を示す。
- **FR-007**: 音名・オクターブ・変化量、臨時記号の明示指定・括弧を保持し、異名同音を演奏音高だけで同一表記に置換しない。
- **FR-008**: 自動臨時記号は調号、小節内の同音名・同オクターブの状態、小節境界に従う。同一譜表の声部間では状態を共有し、譜表・パート・オクターブ間では共有しない。同時点の矛盾は原譜の明示指定を優先し、解決不能なら制限を示す。
- **FR-009**: 各 fixture は安定した識別子、主な確認対象1つ、入力、期待結果、検証段階を持つ。期待結果は必要に応じて記号の種類・数・位置関係・接続先・不在条件を含む。主条件に必要な補助記号は許容する。
- **FR-010**: 基本・境界・不正入力・回帰を別条件として追加でき、失敗時は fixture と不一致条件を特定できること。大きな楽曲1つだけで複数条件を代表させない。
- **FR-011**: fixture は保持情報、生成した描画要素、実際の表示を必要な段階ごとに確認する。描画結果の存在、例外の不在、座標の正常性だけでは対象記号の成功としない。
- **FR-012**: 確認一覧に対象と期待結果を示し、処理失敗・処理完了と、検証の合格・不合格・未検証を区別する。未実施の目視確認を合格と表示しない。
- **FR-013**: 対象記号の欠落、誤った種類や接続先などを含む対照結果で検証の有効性を確認し、各条件が対応する誤描画を検出できること。
- **FR-014**: 記号の追加・修正には可能な限り小さい fixture と期待結果を同時追加・更新する。大きさが必要なら理由を記録し、既存 fixture の識別子を維持する。
- **FR-015**: 旧保存楽譜は変更操作なしで読み続けられる。追加表記情報がない場合は既存の推定を使う。互換性に影響する変更が必要なら移行方法を計画に明記する。
- **FR-016**: 表示省略の警告と演奏上の未解決を区別し、対象箇所・影響・利用可否を示す。正常に表示できる対象に不要な省略警告を出さない。
- **FR-017**: 既存の音高・開始位置・音価・休符・テンポ・拍子・調号・トラック構成・利用可否を回帰確認する。描画処理は元の楽譜を変更しない。

### Key Entities _(include if feature involves data)_

- **音符の表記情報**: 演奏音高に関連する音名・オクターブ・変化量、記譜音価・付点、明示的な臨時記号・括弧。
- **タイ関係**: 対象音・声部・譜表・パート、始点・終点・継続、音楽上と視覚上の指定。
- **描画確認 fixture**: 識別子、1つの主確認対象、入力、期待結果、補助条件、サイズが必要な理由、検証段階。
- **確認結果**: fixture と条件の対応、保持・描画要素・表示ごとの結果、失敗理由、未検証状態。
- **対応状況表**: 表現ごとの各処理段階の状態・影響・優先順位・根拠。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: FR-003 の各基礎条件と US2・US3 の各受け入れ条件に、失敗を個別特定できる fixture が1件以上あり、期待結果と検証段階が100%記録される。
- **SC-002**: 対象の正常な確認用楽譜の100%で、取り込み直後と保存・再読み込み後の表記・接続先・演奏音高・時刻が期待結果に一致する。
- **SC-003**: タイと臨時記号の対象正常条件の100%で描画要素と実表示の確認が合格する。処理完了だけ、または未検証の条件を成功扱いする件数は0件。
- **SC-004**: 各対照確認は対応する条件を不合格にでき、欠落・誤描画の見逃しは0件。結果から失敗した主条件を特定できる。
- **SC-005**: 既存の描画・再生・練習・採点の回帰確認で、描画追加に起因する音楽情報の変更と余分な打鍵要求は0件。
- **SC-006**: 診断を要する全確認条件で、利用者が対象箇所・表示の制限か演奏上の未解決か・利用可否を確認できる。

## Assumptions

- 対応入力は現行の MusicXML 2.0・3.0・3.1・4.0 の score-partwise（XML／MXL）と既存楽譜 JSON。共通表現の保持を4版で確認し、圧縮入力の経路も確認する。MIDI に原譜の音名・タイ表記があるとは仮定しない。
- 今回は新しい演奏表現や採点ルールを追加しない。タイの既存の音楽的意味を維持し、表示拡張との回帰を確認する。
- 特殊符頭、スラー、連符の括弧・数字、強弱、奏法、装飾、歌詞、ペダル、反復展開、微分音、専門的な全記譜対応は対象外。
- 既存 fixtures と開発用一覧を活用し、取り込み確認と描画確認を区別する。自作の最小楽譜を優先し、外部楽曲の追加を必須としない。
- 現状と対象候補の根拠は [investigation.md](investigation.md) に記録する。表示の不具合は fixture 実行で確認し、静的調査だけで表示確認済みと断定しない。
