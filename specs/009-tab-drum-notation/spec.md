# Feature Specification: TAB譜・ドラム譜の取り込みと描画

**Feature Branch**: 既存の作業ブランチを維持（ブランチ作成フックなし）

**Created**: 2026-10-19

**Status**: Draft

**Input**: 「tab譜やドラム譜も描画できるようにしてほしい」。既存の基礎記号・タイ・臨時記号に続き、取り込み・保存・再読み込み後の情報保持と、可能な限り小さいfixturesによる表示確認を継続する。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - TAB譜の弦とフレットを読む (Priority: P1)

利用者はTAB譜を取り込み、指定された弦上のフレット番号とリズムをプレビューし、保存・再読み込み後も同じ運指を読める。

**Why this priority**: 演奏音高だけでは弦とフレットは一意に決まらず、通常譜への置換では運指情報を失う。

**Independent Test**: 6弦TABの指定弦にフレット0を1つ表示する楽譜を取り込み、保存・再取得の前後で弦、数字、開始位置、音価が一致する。

**Acceptance Scenarios**:

1. **Given** 6弦ギターと4弦ベースの各TAB譜、**When** 取り込み表示する、**Then** 弦数に合う譜線とTAB記号が表示され、弦番号1を最上段として指定弦にフレット番号が載る。
2. **Given** 開放弦0、1桁・2桁のフレット番号、同時に複数弦を鳴らす各入力、**When** 表示する、**Then** 数字を読み分けられ、他の数字・譜線・小節線と重ならない。
3. **Given** 音価、付点、休符、上下符幹、旗、連桁、タイを含むTAB譜、**When** 表示する、**Then** 入力で指定されたリズムと継続を読め、通常の符頭や不要な加線・臨時記号が混入しない。
4. **Given** 弦・フレット・チューニング情報を持つ楽譜、**When** プレビュー、保存、再読み込みする、**Then** 元の運指と演奏音高を保持し、描画による再割当てがない。
5. **Given** 弦番号の範囲外、負または非整数のフレット、同一弦・同時刻の相反する指定、**When** 取り込みまたは保存する、**Then** 対象箇所と理由を示し、勝手に別弦へ移さず、失敗した保存で既存内容を部分更新しない。

### User Story 2 - ドラム譜の楽器とリズムを読む (Priority: P1)

利用者はドラムセットの楽譜を取り込み、楽器ごとの位置・符頭とリズムを、保存後も区別して読める。

**Why this priority**: 打楽器の譜面上の位置は演奏音高と別の情報であり、通常の音高計算では正しく読めない。

**Independent Test**: スネア1打とハイハット1打をそれぞれ独立した入力で確認し、指定位置の通常符頭と×符頭が保存後も一致する。

**Acceptance Scenarios**:

1. **Given** バスドラム、スネア、クローズドハイハット、ハイハットペダル、ハイ・ミッド・フロアタム、クラッシュ、ライドの各最小楽譜、**When** 表示する、**Then** 打楽器記号、入力の表示位置、通常または×の指定符頭を確認できる。
2. **Given** 同時打音、足と手の複数声部、上下符幹、休符、連桁・旗・付点、**When** 表示する、**Then** 各楽器と声部のリズムを識別でき、意図しない臨時記号や調号を付けない。
3. **Given** 無音高の表示位置と演奏用の楽器識別を別々に持つ入力、**When** 保存・再読み込みする、**Then** 両方を保持し、表示位置を変更しただけでは鳴らす楽器を変更しない。
4. **Given** 描画情報は完全だが演奏楽器の対応が不明な入力、**When** プレビューする、**Then** 譜面の表示可否と再生・練習・採点の利用可否を別々に示し、別の音へ無断変換しない。

### User Story 3 - 複合譜面と細粒度の回帰を確認する (Priority: P2)

利用者・開発者は通常譜・TAB・ドラムが混在する楽譜を読み、条件ごとのfixturesで欠落や誤配置を検出できる。

**Why this priority**: 新しい譜表の追加が既存の通常譜や改行・改ページの描画を壊すことを防ぐ。P1/P2はすべて今回の必須範囲。

**Independent Test**: 通常譜とTAB、通常譜とドラムの各組み合わせを表示し、各譜表の線数と音符位置を独立検証する。

**Acceptance Scenarios**:

1. **Given** 通常譜・TAB・ドラムの混在または同一パート内の通常譜とTAB、**When** 表示する、**Then** 譜表ごとの種類・線数・配置が独立し、小節と拍の位置がそろう。
2. **Given** 改行・改ページを要する各譜面、**When** 再配置する、**Then** 各ページの譜表記号と継続が判読でき、数字・符頭・タイが欠落・はみ出しを起こさない。
3. **Given** 条件を1つずつ確認するfixturesと欠落・誤種類・誤位置の対照結果、**When** 検証する、**Then** 失敗した条件を特定でき、処理完了・合格・不合格・未検証を区別できる。

### Edge Cases

- 同じ演奏音高でも異なる弦・フレットの表記を維持する。
- 弦情報が欠落した音高だけの入力から運指を推測して「原譜どおり」と表示しない。
- 明示チューニングは保持する。チューニング不明でも弦・フレットが完全なら表示可否を独立に判断する。
- 打楽器の同じ表示位置に異なる楽器がある場合も楽器識別を失わない。
- 原譜で打楽器の表示位置・符頭が明示されている場合、一般的な配置で上書きしない。
- 音高なしの打音と音高不明の通常音符、休符を区別する。打楽器譜の休符も音高なしで保持でき、休符かどうかは音高の有無ではなく休符指定で判定する。
- 線数・符頭・特殊奏法が今回の範囲外なら、対象と表示への影響を診断する。
- TABに対する通常譜との併記は同一演奏イベントを重複した打鍵要求へ変換しない。
- 旧保存楽譜は従来どおり読み、TAB・打楽器の情報を捏造して追加しない。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 譜表の種類、線数と必要な表示設定を譜表ごとに識別し、取り込み・プレビュー・保存・再取得・描画まで保持する。同一パートの異種譜表を扱えること。
- **FR-002**: TABの初期対象は6弦ギターと4弦ベースとし、弦番号1から弦数まで、フレット0–36の整数、単音・複数弦同時発音を表示する。原入力の弦番号と譜線の順序の対応を検証する。
- **FR-003**: TABの弦・フレット・明示チューニングと演奏音高を別々に保持する。音高から運指を自動生成・変更しない。明示された値同士の矛盾は理由と影響を返す。
- **FR-004**: TABの全音符・2分・4分・8分・16分相当の音価、付点、休符、上下符幹、旗、連桁・フック、タイを表示する。音価によってフレット数字の内容を変えず、1桁・2桁の実際の幅を確保する。
- **FR-005**: TABの数字の背景に譜線が貫通して判読を妨げないこと。数字の周囲に必要な間隔を確保し、通常符頭、音高由来の加線、調号・臨時記号を自動付加しない。
- **FR-006**: ドラムの初期対象は5線のドラムセット譜とし、US2/AC1の9楽器を個別確認する。打楽器記号、入力に明示された表示位置と通常・×の符頭を保持・描画する。通常符頭は全音符・2分・黒符頭、×符頭は今回の確認用入力が指定する×を対象とする。
- **FR-007**: 打楽器の演奏楽器識別と無音高の表示位置・符頭を分離する。表示位置を通常の演奏音高へ強制変換せず、音高なしでも描画できること。
- **FR-008**: ドラムの音価、休符、付点、上下符幹、旗、連桁・フック、複数声部、同時打音を表示し、原入力の声部と拍位置を保持する。打楽器譜の休符は音高なしでも保存・再取得・表示でき、音価・声部・所属譜表を保持する。休符には打音の表示位置・符頭・楽器識別を要求せず、タイや発音を付加しない。旧データの数値音高付き休符も引き続き読み、変更操作なしに書き換えない。
- **FR-009**: 不足・矛盾・範囲外情報は対象箇所と影響を返し、表示可能、表示制限、演奏上の未解決を区別する。未対応の楽器対応をピアノ音や通常音高で黙って補わない。描画可能な入力を演奏情報不足だけで描画不能にしない。未対応奏法だけの場合は基本表記を表示して省略を警告し、元情報を保持する。未対応符頭・弦数や必須表示情報の欠落は、不完全候補として元情報を保存でき、譜面描画は不可と理由を示す。通常表記へ無断置換しない。不正な保存入力は拒否する。
- **FR-010**: 描画追加を理由に音高・楽器対応・開始位置・音価・休符・テンポ・拍子・声部・トラック構成を変更しない。再生・練習・採点の新しい規則は追加せず、各譜面の既存機能の利用可否と制限を明示する。
- **FR-011**: 通常譜・TAB・ドラムの混在で譜表ごとの高さと横幅を確保し、小節・拍位置をそろえる。改行・改ページと再配置後にも各記号・数字・継続を表示する。
- **FR-012**: 旧保存データ・既存取り込み形式との互換性を保つ。対象情報を含む入力は実保存・取得を経ても同じ表記となり、不正入力で既存保存内容を部分更新しない。
- **FR-013**: 各記号・条件に1主対象の小さいfixtureを作る。TABは弦位置・開放弦・1桁・2桁・同音異運指・同時弦・各リズム・タイ、ドラムは各楽器位置・通常符頭の各種・×符頭・各リズム・声部・同時打音を独立判定する。混在・改行・改ページは単独条件と別にし、大きさの理由を記録する。
- **FR-014**: fixturesは識別子、由来、入力、期待値、適用する検証段階を持つ。情報保持、描画要素、実表示、必要な実保存取得を区別し、数字の値と弦、符頭の種類と位置、個数、接続先、不在条件を判定する。
- **FR-015**: 数字・符頭の欠落、異なる数字・弦・楽器位置・符頭、不要な記号を含む対照結果を不合格にできること。描画例外がないことや結果の存在だけを成功としない。
- **FR-016**: 既存の確認一覧で対象と期待結果、処理状態と検証状態を示す。未実施・失効した保存検証や目視確認を合格にしない。結果は確認した入力・期待値・配置・描画版に対応付ける。
- **FR-017**: 基礎記号・タイ・臨時記号の既存fixturesと、再生・練習・採点の音楽情報を回帰確認する。描画は原データを変更しない。

### Key Entities _(include if feature involves data)_

- **譜表設定**: 通常譜・TAB・打楽器の種類、線数、譜表記号、適用先と有効範囲。
- **TAB表記**: 弦番号、フレット番号、チューニング、対応する演奏イベント。
- **打楽器表記**: 表示位置、符頭の種類、楽器識別、演奏用対応の有無、声部。
- **表示と演奏の診断**: 対象箇所、理由、表記への影響、各機能の利用可否。
- **確認用楽譜と結果**: 1主条件の入力と期待値、段階別結果、対象版、目視の確認者と実行環境。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: US1–US3の各受け入れ条件とFR-013の各単独条件に、個別に失敗を特定できる確認用楽譜が1件以上対応し、対象・期待値・適用段階の記録率が100%である。
- **SC-002**: 対象の正常なTAB譜・ドラム譜の100%で、取り込み直後と実保存・再取得後の弦・フレットまたは楽器識別・表示位置・符頭が一致する。
- **SC-003**: 対象正常条件の100%で、数字・符頭・位置・リズムと混在・改行・改ページの描画要素および実表示の確認が合格し、未検証を成功扱いする件数は0件である。
- **SC-004**: 対照結果の100%で対応する誤描画または不正入力を検出し、失敗した確認条件と理由を特定できる。
- **SC-005**: 表示拡張に起因する演奏音高・楽器・時刻・音価の変更、重複した打鍵要求、既存通常譜の必須回帰条件の不合格が0件である。
- **SC-006**: 対象の不完全・範囲外入力の100%で、対象箇所と表示への影響、再生・練習・採点の利用可否を区別して確認できる。

## Assumptions

- 利用者の依頼はまず取り込んだ楽譜の表示拡張として扱う。TAB運指の自動生成、TAB・ドラム用の編集UI、ドラム専用採点、新規音源・奏法再現は今回の対象外。
- 入力対象は既存対応のMusicXML 2.0/3.0/3.1/4.0 score-partwise（XML/MXL）と既存楽譜データ。対象共通表現の版別保持と圧縮経路を確認する。MIDIだけから元のTAB運指・ドラム記譜を復元できるとは仮定しない。
- 初期TAB範囲は6弦ギター・4弦ベース、フレット0–36とする。チューニングは入力の明示値を保持し、標準調弦を無言で原譜情報として補わない。
- 初期ドラム範囲は5線・通常符頭・×符頭と上記9楽器。オープンハイハットの○、ゴーストノート括弧、ロール・フラム、特殊符頭、ブラシ記号、1線譜は後続候補とし、省略の診断対象とする。
- TABのベンド・スライド・ハンマリング・プリング・ハーモニクス、カポによる音高導出、7弦以上や5弦ベース、譜表途中の弦数変更は後続候補。明示された未対応情報を別の意味へ置き換えない。
- 008の既存実装とfixturesを基盤にするが、そのDB検証保留・目視証跡不足は解消済みと扱わない。DB検証は利用者指示に従い現環境では未実施のまま区別し、後で専用環境で実行できる手順と検証を用意する。これは保存保持の要件を免除するものではない。
- 調査の静的根拠は[investigation.md](investigation.md)に記録する。今回作成したのは仕様であり、TAB・ドラムの描画が成功したという実行結果ではない。
